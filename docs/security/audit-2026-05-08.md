### MEDIUM — 1 (defense-in-depth)

**SQL identifier interpolation via f-strings** in:
- `src/factorlab/sources/political/_db.py:138-152, 181-224`
- `src/factorlab/storage/ingest.py:301-456`
- `src/factorlab/sources/political/fec/ingest.py:361-365, 502-507`

All **values** are bound via `:name` placeholders (safe). Table /
schema / column names are interpolated from caller-supplied `Table`
objects, `cols` from `rows[0].keys()`, and `where` clauses from
hardcoded literals. No external input flows to identifier
interpolation today; code is safe.

`_db.py:208` constructs a temp-table name from `table.name` raw:

```python
temp_name = f"_copy_{table.name}_{id(rows) & 0xFFFFFF:x}"
```

If `table.name` ever came from user input it would inject. Defense-
in-depth fix: assert table identifiers match `^[a-zA-Z_][a-zA-Z0-9_]*$`
once at the top of `fast_upsert` and `_upsert_copy_then_merge`.

- **Status**: queued — Tier 1 #6 of the 2026-05-08 cleanup plan (identifier whitelist assert at the top of `fast_upsert` and `_upsert_copy_then_merge`).
